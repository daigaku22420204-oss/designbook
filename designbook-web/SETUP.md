# デザインブック 公開手順書

招待した数人だけが使える「デザインブック」を、無料で公開するための手順です。
はじめて行う場合、全部で1時間ほどかかります。順番どおりに進めてください。

---

## 全体の仕組み

| 部品 | 置き場所 | 役割 |
|---|---|---|
| 画面（index.html など） | GitHub Pages（無料） | アプリの見た目と動き |
| データ・写真・ログイン | Supabase（無料プラン） | 投稿・コメント・ノート・写真の保存、ログイン、招待リスト |

- 招待リストに登録されたメールアドレスの人だけがログインでき、データを見たり書いたりできます。
- この判定は Supabase 側で行うので、URL を知られても、招待されていない人はデータに触れられません。

### 無料プランの容量の目安

| 項目 | 無料の上限 | 目安 |
|---|---|---|
| 写真の保存 | 1GB | 写真 約2,000〜3,000枚 |
| 文章・コメント・ノート | 500MB | ノートは1人40MBまで（手書きメモで数百ページ） |
| ノートの写真 | 1人20枚まで | 写真の容量を投稿用に残すため |
| 通信量 | 月5GB | 数人がふつうに使う程度なら収まる見込み |

- 無料プランのままなら、**料金は発生しません**（クレジットカードの登録も不要）。上限を超えると警告メールが届き、その後は翌月まで機能が制限されます。
- **1週間ほど誰も使わないと、Supabase のプロジェクトが一時停止します。** その場合は Supabase の管理画面で「Restore project（再開）」を押してください。データは残っています。
- アプリの「設定」画面に、現在の使用量が表示されます。

## 1. Supabase のプロジェクトを作る（約10分）

1. https://supabase.com を開き、「Start your project」を押します。
2. GitHub アカウントか、メールアドレスで登録します。
3. 「New project」を押し、次のように入力します。
   - **Name**：`designbook`（何でも構いません）
   - **Database Password**：自動生成でOK。念のため、どこかに控えておいてください。
   - **Region**：`Northeast Asia (Tokyo)`
   - **Plan**：`Free`
4. 「Create new project」を押し、準備が終わるまで2分ほど待ちます。

## 2. データベースを準備する（約5分）

1. 左のメニューから **SQL Editor** を開き、「＋」（または「New query」）を押して、出てきた選択肢から **「Create a new snippet」** を選びます。
   - 「Create a new logs query」と「Create a new folder」は使いません。
   - 画面中央に、行番号の付いた白い（または黒い）入力欄が開きます。ここが貼り付け場所です。最初から文字が入っていたら全部消してください。
2. このフォルダの `supabase/setup.sql` をテキストエディタ（Windows はメモ帳、Mac はテキストエディット）で開きます。全選択（Ctrl+A／⌘+A）してコピー（Ctrl+C／⌘+C）し、さっきの入力欄をクリックして貼り付けます（Ctrl+V／⌘+V）。
   - 開くときは、ファイルを右クリック →「プログラムから開く」→ メモ帳 などを選びます。ダブルクリックだと別のアプリが開くことがあります。
3. **貼り付けたあと、SQL Editor の中で**、一番下の行の `YOUR_EMAIL@example.com` を自分のメールアドレスに書き換えます。入力欄で Ctrl+F（⌘+F）を押して `YOUR_EMAIL` と検索すると、すぐ見つかります。前後の `'`（半角の引用符）は消さないでください。
   - ファイルそのものは書き換えないでください。GitHub に置くと誰でも見られるため、メールアドレスが公開されてしまいます。
4. 右下の「Run」を押します。「Success」と表示されれば完了です。
   - 「破壊的な操作が含まれます」という確認が出た場合は、そのまま実行してください（何度実行しても壊れないように作ってあります）。

これで、データの保存場所・写真の保存場所・招待リスト・公式アカウントの作例6件ができます。最初の管理者はあなたです。

## 3. ログインメールについて（基本は設定不要）

**何もしなくてもログインできます。** Supabase から英語のメールが届き、中のリンクを押すとログインできます。

- 初めてログインする人には「Confirm your signup」、2回目以降の人には「Your sign-in link」という件名で届きます。
- 送信元は Supabase（noreply@mail.app.supabase.io）です。届かないときは迷惑メールフォルダを確認してください。
- 招待する人には「英語のメールが届くので、中のリンクを押してね」と伝えておくと迷いません。
- メールの文面を日本語にしたり、確認コードを入れたりするには、下の「任意：Gmail から送る設定」が必要です。

### 送信の上限について

- Supabase に最初から入っているメール送信機能は、**1時間に送れる数がとても少なく**なっています（数通程度）。
- 一度ログインすれば、その端末ではログイン状態が続きます。ふだんは問題ありません。
- 大勢が同時に初回ログインするとメールが届かないことがあります。その場合は時間をおいて試してください。

### 任意：Gmail から送る設定（日本語のメールにしたい・上限を増やしたい場合）

メールの文面を変えるには、Supabase で「カスタムSMTP」（自前のメール送信）の設定が必要です。Gmail を使えば無料で設定できます。
ただし、**送信元があなたの Gmail アドレスになり、招待した人に見えます。**

1. Google アカウントの「セキュリティ」で **2段階認証プロセス** をオンにします。
2. 同じ画面の「アプリ パスワード」で、名前を `Supabase` にして作成します。16文字のパスワードが表示されるので控えます（他の人には教えないでください）。
3. Supabase の **Authentication** → **Emails** → **SMTP Settings**（または「SMTPの設定」）を開き、カスタムSMTPを有効にして次のように入力し、保存します。
   - 送信者メール（Sender email）：自分の Gmail アドレス
   - 送信者名（Sender name）：`デザインブック`
   - ホスト（Host）：`smtp.gmail.com`
   - ポート（Port）：`465`
   - ユーザー名（Username）：自分の Gmail アドレス
   - パスワード（Password）：手順2のアプリ パスワード
4. これでテンプレートが編集できるようになります。**Magic Link** と **Confirm signup** の2つを、次の内容に書き換えて保存します。

**件名**
```
デザインブックのログイン
```

**本文**（「出典」または「Source」タブに切り替えて貼り付けます）
```
<h2>デザインブックにログイン</h2>
<p>下のリンクを押すとログインできます。</p>
<p><a href="{{ .ConfirmationURL }}">ログインする</a></p>
<p>リンクがうまく開かない場合は、アプリの画面にこのコードを入力してください。</p>
<p style="font-size:24px;letter-spacing:4px"><b>{{ .Token }}</b></p>
<p>このメールに心当たりがない場合は、無視してください。</p>
```

5. 送信の上限は **Authentication** → **Rate Limits** で増やせます（例：1時間に30通）。

## 4. アプリに接続情報を書き込む（約10分）

アプリが Supabase につながるように、2つの値をコピーして `config.js` に貼り付けます。

| 必要な値 | 形 | 見つける場所 |
|---|---|---|
| ① Project URL | `https://（英字の並び）.supabase.co` | Data API の画面 |
| ② Publishable key | `sb_publishable_` で始まる長い文字 | API Keys の画面 |

### 4-1. Publishable key（②）をコピーする

1. Supabase の左下の歯車（**Project Settings**）を押し、左の一覧から **API Keys** を開きます。
2. 「**Publishable key**」の表の `default` の行にある、`sb_publishable_…` の右の**コピーボタン**（四角が2つ重なったマーク）を押します。
3. メモ帳などに一度貼り付けて控えておきます。

- 「Secret keys」（`sb_secret_…`）は**絶対に使わないでください。** 全データを操作できる鍵です。
- 「View legacy API keys」（古い anon キー）は2027年に廃止予定なので使いません。

### 4-2. Project URL（①）をコピーする

1. 同じ設定画面の左の一覧で、「INTEGRATIONS」の下の **Data API** を押します。
2. 開いた画面の上のほうにある「**Project URL**」（「API URL」や「URL」と表示されることもあります）の、`https://….supabase.co` の右のコピーボタンを押し、控えておきます。

見つからない場合は、次の方法で作れます。
- 左の一覧の **General** を開き、「**Project ID**」（英字20文字ほど）をコピーします。
- `https://` ＋ Project ID ＋ `.supabase.co` をつなげます。
- 例：Project ID が `abcdefghijklmnopqrst` なら、`https://abcdefghijklmnopqrst.supabase.co`

### 4-3. config.js に貼り付ける

1. zip を展開したフォルダの `config.js` を、右クリック →「プログラムから開く」→「メモ帳」（Mac はテキストエディット）で開きます。
2. 次の2行を探します。
```
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR-ANON-PUBLIC-KEY",
```
3. **`"`（半角の二重引用符）の内側だけ**を、控えた値に置き換えます。`"` と末尾の `,` は消さないでください。
```
  SUPABASE_URL: "https://abcdefghijklmnopqrst.supabase.co",
  SUPABASE_ANON_KEY: "sb_publishable_xxxxxxxxxxxxxxxxxxxx",
```
   - ①を `SUPABASE_URL` に、②を `SUPABASE_ANON_KEY` に入れます（名前は anon ですが、Publishable key を入れて大丈夫です）。
   - 前後に空白や改行が入らないようにしてください。
4. 上書き保存します（Ctrl+S、Mac は ⌘+S）。メモ帳で文字コードを聞かれたら「UTF-8」を選びます。

Publishable key は、画面のプログラムから使う前提の公開用キーです（Supabase の画面にも「Publishable keys can be safely shared publicly」と書かれています）。GitHub で公開されても問題ありません。データは招待リストと権限ルールで守られています。

## 5. GitHub Pages で公開する（約15分）

1. https://github.com でアカウントを作ります（すでにあれば不要）。
2. 右上の「＋」→「New repository」を押します。
   - **Repository name**：`designbook`
   - **Public** を選びます（無料アカウントで GitHub Pages を使うために必要です）。
   - 「Create repository」を押します。
3. 作成直後の画面にある「**uploading an existing file**」のリンクを押します。
4. このフォルダの中身を**すべて**ドラッグ＆ドロップします。
   - 対象：`index.html`、`config.js`、`backend.js`、`manifest.webmanifest`、`assets` フォルダ、`supabase` フォルダ、`SETUP.md`、`README.md`
   - フォルダごとドラッグすれば、中のファイルもまとめて入ります。
5. 下の「Commit changes」を押します。
6. リポジトリの **Settings** → 左メニューの **Pages** を開きます。
   - **Source**：`Deploy from a branch`
   - **Branch**：`main`、フォルダは `/ (root)` を選び、「Save」を押します。
7. 1〜2分待つと、Pages の画面上部にアプリの URL が表示されます。
   - 例：`https://あなたのユーザー名.github.io/designbook/`

## 6. ログイン先の URL を Supabase に登録する（約3分）

1. Supabase の **Authentication** → **URL Configuration** を開きます。
2. **Site URL** に、手順5で表示されたアプリの URL を入れて保存します。
3. **Redirect URLs** の「Add URL」で、同じ URL を追加して保存します。

この設定をしないと、メールのリンクを押したときにアプリに戻れません。

## 7. 動作を確認する

1. アプリの URL を開き、自分のメールアドレスを入れて「ログイン用のメールを送る」を押します。
2. 届いたメールのリンクを押します（またはコードを入力します）。
3. 「設定」画面が開くので、表示名とアイコンを決めて「プロフィールを保存」を押します。
4. 「発見」に公式アカウントの作例6件が並んでいれば成功です。

## 8. 仲間を招待する

1. アプリの「設定」→「招待リスト」に、招待する人のメールアドレスを入力して「招待する」を押します。
2. その人にアプリの URL を伝えます（LINE やメールで）。
3. 相手は URL を開いて、招待されたメールアドレスでログインします。

- 招待をやめたいときは、招待リストの「外す」を押します（2回押すと確定します）。
- 管理者は、他の人の投稿やコメントを削除して整理できます。ただし、他の人の「自分だけ」の採集やノートは見られません。

### スマホのホーム画面に追加する（おすすめ）

- **iPhone（Safari）**：共有ボタン →「ホーム画面に追加」
- **Android（Chrome）**：右上のメニュー →「ホーム画面に追加」

アプリのように起動でき、ログイン状態も保たれます。

## アプリを更新するとき

機能の追加や修正で新しいファイルを受け取ったら、次の手順で反映します。

1. GitHub のリポジトリを開き、「Add file」→「Upload files」を押します。
2. 新しいファイルをドラッグして、「Commit changes」を押します。同じ名前のファイルは上書きされます。
3. 1〜2分待ってから、アプリを再読み込みします。

- `config.js` は上書きしないでください。接続情報が消えます。上書きした場合は、手順4をもう一度行ってください。
- データベースの変更が必要な更新のときは、追加の SQL を一緒にお渡しします。手順2と同じように SQL Editor で実行してください。
- 投稿・コメント・ノートは、この作業をしなくても常にすぐ反映されます。

## 設定を変えたいとき

| やりたいこと | 変える場所 |
|---|---|
| 資料ファイル（PDF・DXF）の添付を使えるようにする | `config.js` の `files: false` を `true` にする |
| ノートに写真を貼る機能を隠す | `config.js` の `notePhotos: true` を `false` にする |
| ノートの容量（1人40MB）を変える | `setup.sql` の一番上の `40 * 1024 * 1024` を変えて SQL Editor で実行し、`config.js` の `noteMB` も同じ数にする |
| ノートの写真の枚数（1人20枚）を変える | `setup.sql` の `select 20` を変えて実行し、`config.js` の `notePhotos` も同じ数にする |
| 管理者を増やす | SQL Editor で `update allowed_emails set is_admin = true where email = '相手のアドレス';` を実行 |

## 困ったとき

| 症状 | 対処 |
|---|---|
| ログインのメールが届かない | 迷惑メールフォルダを確認。送信の上限に達している場合は1時間ほど待つ |
| メールのリンクを押してもログインできない | リンクを長押しでコピーし、ふだん使うブラウザ（Safari や Chrome）に貼って開く。Gmail から送る設定をした場合は、メールのコードをアプリの画面に入力してもよい |
| 「招待されていません」と出る | 管理者が招待リストに登録したアドレスと同じアドレスか確認 |
| アプリが開かない・読み込みが終わらない | Supabase が一時停止していないか確認（管理画面で「Restore project」） |
| Android でカメラが起動しない | 採集フォームの「写真を選ぶ」→ メニューの「カメラ」を選ぶ |
| 「初期設定が必要です」と出る | `config.js` に URL とキーが正しく入っているか確認 |

## バックアップ

無料プランには自動バックアップがありません。大切な採集は、ときどき「設定」→「採集データを書き出す」で保存しておくと安心です。
